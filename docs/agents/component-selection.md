# Choosing Ankvale UI components

Start with the user's task. Reuse the largest suitable composition, then customize its content and behavior. A template owns an application layout and local workflow; a block owns a website section or application workflow; a component owns an interaction. Do not rebuild a composed section from unrelated cards just because the primitives are familiar.

## Full application screens

| Task                                   | Starting point       | Compose or adapt with                                                                            |
| -------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------ |
| Business overview or admin workspace   | `dashboard-template` | `kpi-group`, area/bar charts, `data-grid`, `widget`                                              |
| Inbox and message reading              | `mail-template`      | Search, folders, reader and compose are already included                                         |
| AI assistant or conversation workspace | `chat-template`      | `prompt-input`, `chat-conversation`, `chat-message`, `chat-source`, `chat-tool`, `approval-card` |
| Accounts and sales pipeline            | `crm-template`       | `data-grid` for records, `kanban` for stages, `timeline` for activity                            |
| Portfolio or spending overview         | `finances-template`  | Line/area charts, allocation pie, transaction grid                                               |
| Custom authenticated workspace         | `app-layout`         | Sidebar/navbar/toolbar/aside slots, mobile sheets, `breadcrumb`, `command`                       |

Install an application template as `/r/<name>-template.json`. Read its API at `/docs/templates/<name>`. Pass real data and callbacks as needed; sample actions do not establish authentication, AI, email, payments, or persistence.

## Charts and conversation UI

Choose `line-chart` for a trend, `area-chart` for magnitude over time, `bar-chart` for category comparison, `pie-chart` for a small part-to-whole breakdown, and `composed-chart` only when multiple series types improve understanding. Use a descriptive label, readable axes, and units; do not rely on color alone. Set `animate={false}` for high-frequency updates or deterministic capture.

AI conversations should keep content readable: `Markdown` for safe rendering, `ChatSource` for citations, `ChatTool` for tool status/results, `Reasoning` for an optional concise explanation, `ApprovalCard` for an actual user decision. Never invent hidden reasoning, source links, or execution results to fill a preview.

## Native routing

Use `/native` and `/docs/native/<id>` for native APIs. Native date, time, wheel, phone, swipe and morph controls have their own props. Use `AnkvaleProvider` and React Native `Text`; do not send DOM elements, CSS classes or web registry blocks to Metro. Browser previews establish web rendering only. Check gestures and screen readers on the target device when possible.

## Example assembly plans

A product landing page can start with `NavbarStandard → HeroSplit → LogoCloud → FeatureSplit → PricingCards → FaqAccordion → CtaBanner → FooterColumns`. Omit sections that the brief does not need.

A customer-management screen can start with `AppLayout → CollectionToolbar → CrudCollection → RecordDetail`. Install `app-collection-toolbar`, `app-crud` and `app-record-detail`; supply owned records and real mutation callbacks. Use `EditableGrid` when inline row validation is the main workflow. Return focus after closing editing dialogs.

For a Next.js 404, install `not-found-page`, import `NotFoundPage` in `app/not-found.tsx`, and provide `homeHref` and any meaningful secondary destination. Keep the route a Server Component. Test both an unmatched URL and an explicit `notFound()` path; retain framework 404/noindex behavior.

## Hero artwork and composition

Install `hero-blocks` for all nine compositions and their interactive SVG/product artwork. Use `HeroProduct` for a working project-board preview, `HeroShowcase` for a stepped workflow, `HeroCanvas` for movable cards, and `HeroCentered` for a team network. `HeroSplit` and `HeroStatement` include rotatable vector sculptures; `HeroFramed` and `HeroEditorial` include palette-switching posters; `HeroMinimal` includes a compact content index. Choose one composition that serves the actual product.

Every hero accepts `title`, `description`, `actions`, optional `eyebrow`, `className`, and `headingLevel` (`h2` by default). Set `headingLevel="h1"` for the page's main headline. Newlines in string titles create intentional lines; ReactNode titles work too. Default artwork is included when children are omitted. Pass custom children to replace it, or `children={null}` to omit it. The artwork exports live in `hero-graphics.tsx`. The controls demonstrate local state, not persistence or external services.

Use `/blocks/heroes` to edit copy, inspect desktop/mobile previews and copy source. `/examples/heroes/<variant>` shows each composition as a standalone page. Layouts respond to their container width, so retain their container-query classes when adapting them. Keep animations short, user-triggered or one-shot; preserve reduced-motion handling and the canvas arrow-key controls.

## Additional public component families

Use `typography`, `container`, `stack`, `layout-grid` and `surface` for consistent hierarchy and layout. Use `form` with `FormField` and React Hook Form for validation, field arrays and async submission; spread both `field` and `inputProps` onto the control. `date-picker`, `time-picker`, `date-time-picker` and `period-picker` include single/range exports. Date-time values are wall times with a caller-supplied zone, not implicitly resolved instants.

Use `cascader` for a path, `tree-select` for exact node IDs, `transfer` for two-list membership, and `mentions` for plain-text mention suggestions. Use `chip`, `indicator`, `circular-progress`, `notification`, `popconfirm` and `result` for their specific feedback roles. `bottom-navigation`, `floating-action`, `speed-dial`, `affix` and `tour` cover mobile navigation and guidance. `image`, `image-list`, `image-compare`, `preview-frame` and `qr-code` cover media presentation. Inspect the exact API/example at `/docs/<id>` before composing. These new modules have initial implementations; follow their documented contracts rather than inferring every competitor feature.

## Application workflow blocks

Prefer these compositions before assembling the same workflow from primitives. Registry IDs are installable individually; companion exports share their source module. `/api/blocks.json` identifies that module and `/docs/blocks/<module>` documents its actual props. Source types take precedence over this routing guide.

| -------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Identity and workspace entry     | `app-auth`, `app-password-recovery`, `app-verification`, `app-onboarding`, `app-workspace-switcher`       | AuthPanel `onSubmit` awaits the identity service; recovery and verification callbacks own real credentials/codes. Workspace setup preserves drafts; service success determines navigation and session state.                                                                                                 |

| Billing                          | `app-billing`, `app-invoice`                                                                              | Provide actual plans, usage, invoices and payment-method/upgrade/download actions. Use a payment provider for financial credentials.                                                                                                                                                                         |
| Developer settings               | `app-integrations`, `app-api-keys`, `app-audit-log`                                                       | Connect real services, return the actual one-time secret from ApiKeysPanel `onCreate`, and supply audit records. `WebhooksPanel` is also exported by `app-integrations.tsx`.                                                                                                                                 |

## Rich controls and data adapters

Use `text-field` for TextField/SearchField/PasswordField with persistent labels, clear/visibility actions and controlled values. Use `selection-field` for async/creatable single or multiple selection; `loadOptions(query, signal)` must respect cancellation. Use `number-field` for locale-aware numeric drafts and bounds; canonical percentages store 0.125 for 12.5%. Use `color-picker` for normalized solid colors, not gradients.

Choose `editable-grid` for validated row drafts: own `data/onDataChange` and await `onCommit`. For rectangular entry, pass `spreadsheet` or use its `SpreadsheetGrid` export. Shift+arrows/click selects a rectangle, Copy/Paste carries quoted TSV, and Save awaits `onBatchCommit(changes)` with `{previous, row}` entries. Canonical returned rows must match exactly the edited IDs. Invalid/rejected drafts remain editable; the backend must enforce atomic persistence and optimistic versions. The bounded matrix does not append rows, provide fill handles, virtualize or import Excel formulas. Existing column visibility/order/filtering and successful-batch undo/redo apply in EditableGrid.

Choose `server-data-grid` when the service owns search/sort/filter/page: stable `source(query, {signal})` returns `{rows, rowCount}`. Use `query-builder` for a controlled `QueryGroup` (`value`, `fields`, `onChange`) with nested all/any groups and typed text/number/date/boolean/enum rules. `validateQuery`/`compileQuery` from `lib/query` validate and evaluate the structured AST; dates are calendar days, not zoned instants. Pass `filterTree` to ServerDataGrid. `onExport({format, query})`, `exportFormats` and `onPrint(query)` delegate actual CSV/XLSX/PDF/print generation; the application chooses current page versus all matches. Validate again and bind values in the backend adapter; no SQL translator or document writer is implicit.

`collection-list` adds grouped selection, reorder/load-more callbacks and optional virtualization; validate real viewport measurements. `tree` adds lazy exact-node selection, rename and movement callbacks; the owner validates hierarchy changes, and checkbox propagation is not automatic. `avatar-picker` supports searchable assignment and overflow presentation.

Use `upload-manager` for a bounded concurrent queue. Its `upload(file, {signal, onProgress, relativePath})` transport owns real progress/cancellation and storage-path policy. `allowDirectory` supports native directory selection and recursive drops where the browser supplies directory entries; unsupported browsers fall back to ordinary files. Traversal is bounded and staged before enqueueing. Relative paths preserve same-named files in different folders; they do not authorize storage keys.

Use `image-cropper` for source-coordinate raster cropping. Pass `source: Blob | string | null`, `alt` and `onCrop(blob, crop, {signal})`; keep the real returned Blob type and honor cancellation. It supports position/size/aspect controls and bounded output, with CORS required for remote sources; it does not rotate images or edit EXIF. Bridge `UploadManager.beforeUpload(file)` through an application-owned serialized crop-dialog queue and resolve a new File only after save. Reject cancelled requests and settle queued requests on unmount; `beforeUpload` itself does not receive a cancellation signal.

Use `scheduler` for simultaneous resource-day lanes, bounded daily/weekly recurrence and per-occurrence editing/skipping. Pass `timeZone`, a deterministic `initialDate`, owned events and `onEventsChange`; `onSave(updatedSeries)` must succeed before publishing updates. `updateOccurrence(series, occurrenceKey, overrideOrNull)` preserves instance identity using its original local date. Built-in `resolveZonedWallTime` rejects nonexistent DST times and requires an earlier/later choice for overlaps; recurrence `gapPolicy` chooses skip/reject, and `disambiguation` handles future overlaps. Supply `resolveWallTime` only for a custom domain policy. Recheck expanded conflicts on the server. Resource lanes use the configured IANA zone; the optional read-only Agenda calendar explicitly uses browser timezone. This is not a full RFC 5545 recurrence engine.

Use `advanced-chart` for scatter/bubble/heatmap/funnel/gauge/candlestick/radial/sparkline/acyclic multistage Sankey; retain the exact-value table and units. Scatter/bubble/sparkline/candlestick offer bounded geometric pan/zoom and an X-range brush with keyboard equivalents; use controlled `viewport/onViewportChange` when range state belongs to the application. `data-analysis` accepts `computedColumns` and optional `numericFields`; computed results participate in numeric aggregates/pivots. Compile reusable arithmetic dependency graphs with `compileComputedColumns(columns, inputFields)` from `lib/grid-analysis`, then `evaluate(record)`. Unknown references, cycles, invalid inputs and division by zero fail explicitly. Expressions support identifiers and numeric arithmetic without eval, property access, calls or spreadsheet functions; use an explicit numeric schema for empty/heterogeneous datasets. Existing templates accept `configuration` for brand, identity, pages, navigation, actions and custom page rendering; adapt those slots before forking the template. Consult implementation/API docs for remaining advanced boundaries.

## Shared defaults and animation

Install `ankvale-provider` near a client boundary and pass explicit product preferences: `locale`, `timeZone`, `direction`, `density`, `appearance`, `motion`, optional `toasts`. It scopes defaults without storage or document mutation. Keep `appearance="inherit"` with a server-themed site; `appearance="system"` uses `serverAppearance` during SSR. Density currently affects standard Input/Select heights; locale defaults do not automatically translate every control. External `portalContainer` targets need matching styles, appearance, language, direction and motion scope. Avoid clipped/transformed ancestors for fixed overlays.

Use CSS feedback for controls and the existing `motion` module for one-shot section entrances. Install `animation` for `Presence present`, `AnimatedSwitch stateKey`, `AnimatedLayout`, `AnimatedList`, `AnimationGroup` and `ReorderList items/onItemsChange`. Keep Presence mounted outside its condition; it does not replace dialog focus management. Use stable item/layout IDs and keep focused fields outside remounting switches. Durations are milliseconds, with shared 120/180/280/160ms tokens. `AnkvaleProvider motion="none"` and `AnimationProvider disabled` opt out; nested scopes cannot override an explicit opt-out.

Motion for React (`motion/react`) powers presence/layout/reorder. GSAP, Lottie and Three.js remain optional project integrations for specific timeline, authored animation or 3D assets; lazy-load them, supply static alternatives and clean up on unmount. Honor `useReducedMotion` and media visibility. Do not wrap already animated blocks or Base UI overlays in duplicate entrances. Read [motion-guide.md](motion-guide.md) for lifecycle and accessibility requirements. Browser checks remain necessary for pointer drag, interpolation and overlay geometry.
