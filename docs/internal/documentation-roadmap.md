# Documentation coverage and roadmap

This is the documentation backlog, not a claim that every topic is implemented. Keep ownership, release/version and last-reviewed evidence with each topic as the system grows. Do not publish speculative APIs as working features.

## Foundation supplied in this handbook

- Project purpose, audience, intentions and visual principles.
- Current versus planned installation/distribution, with website/runtime separation.
- Supported technology status and compatibility boundaries.
- Template/block/component selection and application service ownership.
- Color, typography, UI, density, theme and motion customization.
- Icons, illustrations, graphics, asset rights and reduced-motion rules.
- Agent setup, skills, MCP, local docs and trust boundaries.
- Repository architecture, maintenance and verification workflow.
- Accessibility/security expectations and known certification limits.
- Package credits, exact dependency versions, provenance and license evidence.
