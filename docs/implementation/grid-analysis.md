# Clipboard grid and computed columns

`SpreadsheetGrid` is exported from `@ankvale/ui/components/editable-grid`. `EditableGrid` opts into it with `spreadsheet`; row-edit mode remains the default. Both accept `onBatchCommit(changes)` for application persistence.

Each change contains `{ previous, row }`. The grid parses all incoming cells before staging a batch, runs the existing column validators, retains invalid drafts beside their cells, and publishes `onDataChange` after a successful Save. Rejected async commits retain the draft for retry. Returned canonical rows must contain exactly the edited row IDs. Clipboard edits cannot change a row identifier. If EditableGrid has `onCommit` without `onBatchCommit`, spreadsheet saves report the missing batch integration; separate row requests cannot promise transaction semantics.

Use Shift + arrows or Shift + click to select a rectangle, and Ctrl/Cmd+A to select the matrix. Native Copy/Paste events read/write quoted TSV, including tabs, newlines and quotes inside values. Enter/F2 or double-click opens a cell editor; Enter stages a value and Escape cancels the editor. Copy preserves raw stored strings. There is no JavaScript formula execution or Excel formula import. Read-only destinations, parser failures and matrix overflow reject the whole paste. Validation errors remain editable until Save succeeds or Discard removes the draft.

The matrix is bounded by the supplied data. It does not append rows, replicate a single value across a larger selection, provide fill handles, cut/delete ranges or virtualize. Pass a suitably sized page for large datasets. Coordinates address the supplied row/column order. EditableGrid applies current column visibility/order and filters; successful spreadsheet batches participate in its undo/redo. Group headers, spans, row details and summaries remain features of its ordinary DataGrid view.

Supply immutable rows with stable IDs. Save shallow-compares source fields against each staged base row and rejects records changed before Save. Unrelated source rows received during an async commit are preserved. The application batch callback must enforce authorization, optimistic versions and atomic server persistence. Client state cannot guarantee server isolation or undo partially persisted requests.

`compileComputedColumns(columns, inputFields)` in `@ankvale/ui/lib/grid-analysis` validates identifiers, duplicate/input collisions, unknown references and cycles before producing deterministic topological `order` and `evaluate(record)`. Evaluation returns a fresh numeric record with the computed fields. Compile once and evaluate many rows. Compilation caps graphs at 1,000 computed columns and expressions at 10,000 characters/128 nesting levels. Expressions support numeric identifiers, decimal literals, unary minus, parentheses and `+ - * /`. Missing/non-finite inputs, division by zero and non-finite results throw. The parser uses an arithmetic tree, with no eval, property access, calls, scripts, spreadsheet cell references or spreadsheet functions.

`DataAnalysis` accepts `computedColumns` and optional `numericFields`. Computed values participate in aggregates, pivots and the formula view. Invalid graph/input errors appear as alerts. Pass an explicit numeric schema for empty or heterogeneous datasets. `serializeDelimitedRows` and `parseDelimitedRows` are standalone clipboard transport helpers.

Verification: `node scripts/test-tooling.mjs tests/grid-analysis.test.tsx` covers arithmetic grammar, dependency ordering/cycles/unknown references, quoted TSV, keyboard rectangles, copy/paste, staged validation, parser rejection, async failure/retry and integrated analysis. Physical browser clipboard and assistive-technology verification remain separate from the DOM harness. This is a practical data-entry and analytics layer, not an Excel-compatible spreadsheet engine.
