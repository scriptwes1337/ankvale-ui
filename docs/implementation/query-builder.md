# Nested queries and export adapters

`QueryBuilder` provides a controlled recursive editor: pass `value: QueryGroup`, `fields` and `onChange`. Field types are text, finite number, calendar date, boolean and enumerated values. Text offers equality, containment/prefix/suffix and membership; numbers add ordered comparisons/ranges; dates use validated `YYYY-MM-DD` calendar days; boolean/enum controls preserve their value types. Conditions can be nested in all/any (AND/OR) groups. Dates represent days without timezone conversion. Text comparison is case-sensitive unless the rule sets `caseSensitive: false`.

Use `validateQuery`, `compileQuery` and `QueryValidationError` from `@ankvale/ui/lib/query`. Validation checks the root/group/rule structure, unique IDs, known fields, supported operators, correctly typed values, finite numbers, enum membership, real calendar dates, ordered ranges and nonempty membership lists. Empty root queries match all rows; empty nested groups are invalid until populated or removed. Missing/null/empty-string values match only `isEmpty`/`isNotEmpty`; invalid typed source values do not satisfy ordinary comparisons, including `neq`/`notIn`. Arrays in source records are not multivalue fields in this version.

The default limits are 6 group levels and 200 total nodes. Limits normalize to finite integer bounds and are capped at 20 levels/10,000 nodes. Evaluation compiles validated structured predicates without SQL interpolation, property-path traversal or code evaluation. Literal membership/range arrays and the compiled child lists are snapshotted. It reads own properties by field ID, or an explicitly supplied typed field getter. A getter is ordinary application code and must be safe for the provided records. Invalid external query structure gets a reset action rather than unbounded recursive rendering. A disabled fieldset disables editing. The caller owns persistence, presets and request debouncing.

`GridQuery.filterTree` and `ServerDataGrid.filterTree` carry the same typed AST through source, export and print callbacks. Existing flat filters remain supported. Validate before sending an edited query to a backend; the backend must independently validate fields/operators, enforce access controls and bind values using its data adapter. The client predicate is not a SQL translator and does not promise database collation/timezone parity.

`ServerDataGrid.onExport({ format, query })` delegates CSV/XLSX/PDF generation to the application/backend. `exportFormats` controls which buttons appear. `onPrint(query)` delegates print preparation. Both await promises, disable concurrent toolbar actions and display rejected-request errors. They receive the current search, sort, page and filter query; the application decides whether an export covers the current page or all matches. No workbook/PDF writer, browser print side effect, network endpoint or file download is fabricated by these slots.

The standalone demo is `apps/web/components/query-previews.tsx`; its static names list is `apps/web/lib/query-preview-names.json`. Test with `node scripts/test-tooling.mjs tests/query-builder.test.tsx`. Checks cover nested predicates, literals/types, dates, empty values, malformed input, bounded recursion, controlled editing and real export/print callback payloads/errors. Screen-reader and physical browser interaction checks remain separate.
