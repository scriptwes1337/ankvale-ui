# Application blocks

B01–B34 now have initial public frontend implementations in `packages/ui/src/blocks/app-*.tsx`. The 34 primary variants are listed in `apps/web/lib/app-block-definitions.json` and have local-state examples in `app-block-previews.tsx`. Root integration supplies their registry manifests, gallery routes and generated API pages.

These are reusable application sections and workflows, not authentication, payment, mail, upload or authorization services. Their data and async callbacks belong to the consuming application. Preview callbacks update local sample data or return explicitly labeled preview results; no network service is called by the examples.

## Important contracts

- **Authentication:** AuthPanel separates sign-in from sign-up. Existing credentials are not subjected to a new password-length policy at sign-in. `minimumPasswordLength` configures sign-up policy; actual authentication and policy enforcement remain server responsibilities. Social actions are slots. PasswordRecovery supports request/reset/expired states; VerificationPanel supports verification and recovery-code entry, caller-provided recovery codes and resend cooldown. Supply real service callbacks.
- **Onboarding:** pass `initialDraft` to resume; `onDraftChange` lets the owner persist progress and fields. Creation/joining callbacks determine actual membership and invitations. Invite-email text is passed to the service for parsing and validation; no invitations are sent automatically.
- **Settings and access:** membership, sessions and preference data are controlled by the owner. MembersPanel exposes invitation, role-change, revoke and remove callbacks. PermissionsEditor accepts exact grants and optional inherited grants; inherited values are displayed read-only. It does not calculate role inheritance or enforce authorization. `canManage` changes the available UI; backend policy still determines actual access. SecuritySettings accepts an MFA setup slot, allowing VerificationPanel or the application's auth-provider flow.
- **Billing/payments:** price labels and invoice amounts are supplied by the owner. BillingOverview exposes plan/cancellation/invoice actions; payment-method editing is a provider slot in InvoiceDetails. CheckoutFlow accepts a payment UI slot and awaits a service receipt before showing confirmation. It never collects raw card fields or manufactures a successful order. Address edits and rejected-order retries retain the shipping draft. Cart/order arithmetic is presentation; the service calculates authoritative prices, stock, tax, shipping and payment outcomes.
- **Money:** commerce values are integer minor units; `formatMoney` uses the currency's decimal exponent, including zero-decimal currencies, with a deterministic `en-US` default locale and optional explicit locale. Use one display currency in a price-sorted catalog, or sort externally after currency conversion.
- **Secrets/integrations:** ApiKeysPanel displays a secret only after `onCreate` returns it, supports explicit copy/hide and never generates a production secret. Revoke/connect/disconnect/webhook callbacks are provider-neutral. Webhook delivery logs and retries use service-owned data.
- **Search/logs:** GlobalSearch debounces input, passes an AbortSignal, cancels on replacement/unmount and ignores aborted results. Recent queries are supplied by the owner. AuditLog has local query/date filtering, detail disclosure, pagination and an export callback. NotificationCenter supports unread filtering, read/dismiss/read-all and pagination callbacks.
- **Collection UI:** CollectionToolbar emits a query, flat AND-style rules (contains/equals/not), date bounds and saved-view actions. It does not execute a backend query. CrudCollection exposes table/list/card modes, create/edit/delete dialogs and selection/bulk-delete callbacks; all supplied record fields are strings. DataGrid remains the starting point for complex typed columns, large datasets or spreadsheet editing. RecordDetail composes descriptions, action slots and content tabs.
- **Import/export:** ImportExportWizard accepts UTF-8 CSV files under 5 MB, quoted commas/newlines/escaped quotes, header mapping, required-field and optional pure per-field validation, unique-key duplicate detection, a preview and async import result. Only valid rows are passed to `onImport`; preview rows are capped, while processing is in memory. XLSX, large background imports, cross-database duplicate detection and service progress streaming are later adapters. Export is an explicit callback, not an invented download.
- **Files:** FileManager supports root/folder navigation, list/grid views, search, upload, preview, rename, move, sharing and confirmed delete. It excludes moving a folder into itself/its descendants. Service callbacks own persistent folders, uploads, access links and recursive deletion policy. Image previews use the shared Image component; other files open only a caller-provided URL.
- **Projects/comments:** ProjectDetail has board/list/calendar views, task editing, assignees and due-date fields. Calendar mode filters tasks by selected date; it is not a resource scheduler. Kanban moves emit updated tasks through an async callback. CommentThread supports replies, edit, resolve, plain-text mentions and attachment callbacks. Mention suggestions are supplied through `mentionOptions`; attachment handling is caller-owned.
- **Booking:** availability dates, display labels and a timezone are supplied. The service returns the booking receipt and handles conflicts, timezone resolution, cancellation and rescheduling. The block does not infer availability from a local clock.
- **Guidance/content:** SetupChecklist uses controlled completion/skipped flags and action callbacks. HelpCenter searches supplied article metadata and displays supplied article content plus a support callback. FeedbackForm passes category, description, reply email and selected attachments to its submit callback.
- **App states/safety:** AppStatePage presents unauthorized, forbidden, error, offline, maintenance, unavailable and expired-session states. The route owns HTTP status, recovery destinations and error-boundary behavior. UnsavedChangesDialog handles in-app decisions when opened by the owner; useUnsavedChangesWarning covers browser unload, not a universal router interceptor. DangerZone requires an exact name confirmation and offers a reauthentication slot before the async delete callback.

## Verification

`node scripts/test-tooling.mjs tests/app-blocks.test.tsx` passes. The suite renders all 34 examples, checks sign-in/sign-up policy distinction, rejected auth value retention, onboarding drafts, member role and permission changes, unread notifications, CRUD create/dialog/view switching, controlled filter rules/reset, search cancellation, quoted CSV/duplicate import, booking receipts, help search/article display, exact delete confirmation and rejected checkout retry with retained shipping data.

Package TypeScript checks pass. Focused ESLint over `app-*.tsx` and `app-block-previews.tsx` has zero warnings/errors (the repository config emits a generic Pages-directory notice when invoked from the repo root). Browser, full locale, screen-reader and mobile-device coverage are not established by these tests; root integration should include representative browser review and the consumer/API/build checks.
