# Missing-component implementation

First implementation pass, 26 November 2026. The 38 component/utility families C01–C38 from the frontend-system audit now have public source modules, individual install manifests, generated API pages and independently loaded previews. The web catalog grows from 121 to 159 component modules. This pass does not implement the separate E01–E21 enhancements or application/marketing blocks, and does not migrate or publish the npm package.

## Find and use them

Browse `/playground#<id>` and `/docs/<id>`. The code example on each API page uses consuming-project imports and can be copied into a client component. Source modules are in `packages/ui/src/components/<id>.tsx`; `use-media-query` is a hook. Registry consumers can install `/r/<id>.json`. The existing workspace exports already expose the new modules. npm-first packaging remains a separate delivery step.

## Contracts and deliberate boundaries

- **Form:** React Hook Form supplies validation, field arrays, reset, dirty state and async submit state. `FormField` connects a persistent label, description and error to the rendered control through `inputProps`. Spread both `field` and `inputProps`; retain `field.ref` so error focus works. Use `rules` or your own resolver. `Form` catches a rejected submit callback, announces its configurable error message, retains values and guards duplicate submissions. Disable the submit button with `formState.isSubmitting`; call `setError` for field-specific server errors. The form has `noValidate`, so validation rules must be configured rather than relying on native `required` alone.
- **Date inputs:** values are date-only `YYYY-MM-DD` strings. Parsing is strict and uses local calendar fields, avoiding UTC date shifts. DatePicker combines a keyboard-native date field with an Ankvale calendar popover, limits, presets and clear. DateRangePicker validates ordering and supports preset ranges. Browser-native date and time field segment formatting follows the browser locale; the calendar `locale` prop controls the popup. Exhaustive browser/calendar-system fidelity is not claimed.
- **Time inputs:** values are local `HH:mm` (optionally seconds according to `step`); `step` is seconds. TimeRangePicker defaults to same-day ordering; opt into overnight ranges explicitly. The native browser picker/spinner supplies keyboard entry.
- **DateTime inputs:** values are wall-clock `YYYY-MM-DDTHH:mm` strings with an explicit displayed IANA timezone supplied by the caller. They do not silently turn a wall time into an instant or guess a daylight-saving overlap/gap. Domain code resolves that ambiguity before saving. DateTimeRangePicker compares wall times in the same declared zone.
- **Periods:** ISO month/week, `YYYY-Qn` quarter, or numeric year. PeriodRangePicker shares the format and validates order. Quarter entry uses a text pattern; when used inside Form, configure a matching validation rule. Native month/week controls depend on browser support. Full custom period calendar panels are future enhancements.
- **Cascader:** path values are arrays; changing a parent clears descendants. Search covers loaded paths. Optional `hasChildren` and abortable `loadChildren(path, signal)` support lazy branches with loading, retry and cancellation. Keep loaders stable across parent renders. Empty string is reserved for the unselected option.
- **TreeSelect:** a searchable hierarchical list of native checkbox/radio controls inside a Base UI popover. Multiple mode selects exact node IDs independently; selecting a parent does not implicitly select descendants. Data may be replaced by the caller. Automatic checkbox propagation, collapsed/virtualized branches and a dedicated lazy-loading UI are not included in this first implementation; generic tree depth remains in E09.
- **Transfer:** searchable available/selected lists, native keyboard selection, disabled items, responsive stacking and focus restoration to moved items. Supply unique stable IDs. The owner controls persistence.
- **Mentions:** plain-text `@value` tokens with keyboard suggestion selection, dismissal and cursor insertion. `onQueryChange`, `options`, `loading` and `error` let the caller supply asynchronous suggestions; the owner cancels/ignores stale requests. This is not a rich-text mention document model.
- **Feedback:** Chip exposes separate selection and removal buttons. Indicator has an accessible count label; Status pairs a dot with text. CircularProgress does not import a chart engine. Notification is persistent until its owner dismisses it. Popconfirm awaits its callback and retains an error/retry state if it rejects. Result is a panel, not a replacement for route-level HTTP error handling.
- **Navigation:** BottomNavigation uses real anchors by default; optional `onNavigate` lets a client router own navigation. FloatingAction is inline unless viewport placement is requested. Place bottom navigation and floating actions in shell slots with reserved clearance; do not overlap content. SpeedDial delegates keyboard/menu semantics to Base UI. Affix is CSS sticky and inherits its scroll container; BackToTop focuses the requested destination and respects reduced motion.
- **Images:** URL/data-URL sources, alt text, lazy loading, error fallback, lightbox, bounded zoom and scrollable panning, grouped previous/next controls and Escape/focus behavior through Dialog. ImageList preserves source order. ImageCompare uses a labeled native range input for keyboard and pointer operation. Images in the demos are code-native SVG fixtures, with no external asset requests.
- **QRCode:** generated SVG with a four-module quiet zone, active/loading/expired states, refresh callback and SVG download. Uses the `qrcode` engine, not a decorative imitation. Values that cannot be encoded produce an error. Keep the black/white contrast and quiet zone; do not hide arbitrary logos over the code.
- **Tour:** controlled open/step state supports saving/resuming externally; highlights and scrolls to an optional target, positions the dialog within the viewport, and falls back to a centered dialog when no target is available. Modal focus and dismissal come from Dialog. Target outlines are restored on step change/close. Keep target callbacks client-side. Test dynamic targets and unusual scroll containers in the consuming app.
- **Countdown:** absolute deadline in epoch milliseconds; no timestamp-dependent SSR output. It refreshes after hydration and calls onExpire once per deadline. `paused` freezes the display refresh; the absolute deadline keeps advancing. It does not announce every second.
- **Layout/media helpers:** Masonry uses CSS column-major reading order; it does not reorder DOM to simulate left-to-right rows. LayeredStack is for static presentation; avoid placing interactive controls in obscured cards. PreviewFrame is display chrome, not a mobile-device simulator. AttachedGroup expects direct control children.
- **Content/environment:** ContentTransition is a short entrance for deliberately replaced content; do not put an actively focused control inside content that will remount. Swap renders only the active branch; the owning control supplies toggle semantics. ClientOnly uses a stable server fallback and switches after hydration. useMediaQuery accepts a stable server fallback, subscribes to live match changes, and cleans up listeners.

Two implementation dependencies were added: `react-hook-form` and `qrcode`, with QR type declarations for source consumers. No new animation engine or icon family was added.

## Verification

The targeted suite is `npm run test:system-components`. It covers all 38 preview renders and install/API coverage, plus form validation/focus/arrays/rejection/deduplication, strict dates/ranges, cascader reset and lazy loading, transfer movement/focus, mention insertion, multi-selection/reset, confirmation failures, notifications, image errors/gallery/zoom, progress bounds, QR states and tour progression. Additional checks: generated API example type checks, consumer aliases, repository types/lint, agent guides and production build.

Browser checks cover form error focus, calendar selection/focus return, transfer and hierarchical selection, image preview, QR rendering and tour positioning. Representative selectors, media and tours are checked in a 400px Chrome responsive viewport; these are browser checks, not physical mobile-device or screen-reader certification. Broader locale, assistive technology, performance and visual-regression matrices remain release hardening work.

Verified for this pass: targeted system-component tests, all 159 generated API examples, 184 consumer TypeScript source files, repository type checks/lint, agent-guide/motion checks, and the production build (253 static pages) pass. Browser review found and corrected the mobile tour translation, duplicate calendar affordance and transfer focus loss.
